## 결정

- 계산 범위는 단일 GPU로 제한한다.
- Hugging Face 메타데이터의 정확한 파라미터 수를 우선 사용한다.
- 메타데이터가 없으면 지원하는 decoder-only `config.json` 구조에서 파라미터 수를 추정한다.
- 구조를 안전하게 추정할 수 없으면 사용자가 파라미터 수를 직접 입력한다.
- 필요한 VRAM은 `모델 가중치 + KV 캐시 + 추가 메모리`로 계산한다.
- 추가 메모리는 기본값으로 `(모델 가중치 + KV 캐시) × 20%`를 사용한다.
- 세 메모리 항목은 서로 섞이지 않는 액체층으로 표시한다.
- 합계가 GPU VRAM을 넘으면 액체가 병 밖으로 흐르는 OOM 상태를 표시한다.

## 이유

- 첫 질문은 처리량보다 모델 자체가 GPU에 적재되는지 여부다.
- `config.json`만으로 모든 아키텍처의 파라미터 수를 정확히 복원할 수 없다.
- 모델, KV 캐시, 런타임 여유를 분리하면 OOM 원인과 각 입력의 영향을 바로 이해할 수 있다.
- 단일 GPU 가정은 tensor parallel과 장치별 분할 규칙을 숨기지 않고도 계산을 단순하게 유지한다.
