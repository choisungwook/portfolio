# iOS 공유 시트 단축어 설정

- 준비: 접근 가능한 Reader 주소와 웹 설정에서 발급한 API 토큰
- 서버 배포·Access 설정은 #1216 범위
- 이 문서는 단축어 앱에서 직접 구성하는 절차, 서명된 설치 파일은 미제공

## 단축어 만들기

1. 단축어 앱에서 새 단축어 생성, 이름을 akbun reader 저장으로 지정
2. 세부사항에서 공유 시트에 표시 활성화, 입력 유형은 URL만 허용
3. 단축어 입력에서 URL 가져오기 액션 추가
4. 목록에서 항목 가져오기 액션으로 첫 번째 URL 선택
5. URL 콘텐츠 가져오기 액션 추가, 아래 표의 값 입력
6. 응답 사전에서 id 값 가져오기
7. id가 있으면 저장 완료 알림 표시; 없으면 응답의 error를 알림으로 표시

| 항목 | 설정 |
| --- | --- |
| 주소 | Reader 주소 뒤 /api/documents |
| 방식 | POST |
| Authorization 헤더 | Bearer, 공백 한 칸, 발급한 토큰 |
| Content-Type 헤더 | application/json |
| 요청 본문 | JSON |
| url | 4번에서 선택한 URL 변수 |
| tags | 선택 입력, 텍스트 배열 |

JSON 요청의 형태는 아래와 같다. 실제 단축어에서는 url 값에 공유 URL 변수를 연결한다.

```json
{
  "url": "https://example.com/article",
  "tags": ["읽기"]
}
```

## 실패와 재시도

- 저장 완료 알림: URL이 DB에 저장되었다는 의미, 본문 추출은 이후 처리
- 연결 오류로 단축어가 중단되면 네트워크 확인 후 같은 글을 다시 공유
- 재전송으로 같은 문서가 중복 생성되지 않음
- 401: 웹에서 새 토큰을 발급하고 단축어의 토큰 교체
- HTML 로그인 화면이 응답하면 Access의 자동화 API 경로 설정 확인
- 전체 사이트 Access 정책이 Bearer 요청을 앞단에서 차단하면 Worker 코드만으로 해결 불가; #1216에서 경로 정책 검증 필요
- 본문 실패: Reader에서 원문 링크로 읽기, URL 저장은 유지
- 토큰이 포함된 단축어 공유 금지, 기기 분실 시 웹 설정에서 해당 토큰 폐기

## 실기기 확인

- Safari와 다른 앱의 공유 메뉴에서 URL 저장
- 받은 글 목록에 문서 한 건 생성, 새로고침 후 본문 표시
- 같은 URL 재공유 후 중복 없음
- 비행기 모드에서 연결 오류 확인, 복구 후 재공유
- 토큰 폐기 후 저장 거절 확인
