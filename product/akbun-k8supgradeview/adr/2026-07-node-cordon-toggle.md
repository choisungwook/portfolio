## 결정

Nodes 탭 노드 행 끝에 Action 칼럼을 두고 버튼 하나를 놓는다. 버튼 글자는 노드의 `spec.unschedulable` 값에 따라 Cordon 또는 Uncordon으로 바뀐다. 별도의 "cordon 활성화" 칼럼은 만들지 않는다.

실행 전에 main 프로세스가 dialog로 한 번 묻고, 취소하면 kubectl을 실행하지 않는다. 노드 이름은 IPC 경계에서 검증하며 `-`로 시작하는 값은 거부한다.

## 이유

- cordon 여부는 이미 Status 칼럼의 SchedulingDisabled로 보인다. 상태를 보여주는 칼럼을 하나 더 만들면 같은 값을 두 곳에서 그리게 되고, 한쪽만 고치는 실수가 생긴다. 버튼 글자를 상태에서 파생시키면 그릴 곳이 하나다.
- 두 버튼을 나란히 두고 상황에 따라 비활성화하는 방식도 있었지만, 활성/비활성 조건을 두 벌 관리해야 한다. 토글 하나는 분기가 `unschedulable` 한 곳뿐이라 유지보수가 쉽다.
- 이 앱에서 처음으로 클러스터 상태를 바꾸는 동작이다. 조회는 잘못 눌러도 되돌릴 것이 없지만 cordon은 다르므로 확인 절차를 둔다. 확인을 renderer의 confirm이 아니라 main의 dialog로 두면 실행 직전 지점과 확인 지점이 같은 프로세스에 있어 우회할 경로가 없다.
- 노드 이름은 shell을 거치지 않아 injection은 없지만 `-`로 시작하면 kubectl이 옵션으로 읽는다. 조회와 달리 실행 결과가 클러스터에 남으므로 인자 형태를 먼저 막는다.
- 행 클릭은 파드 조회에 이미 쓰고 있어 버튼 클릭에서 이벤트 전파를 멈춘다. 실행 중에는 버튼을 잠가 같은 노드에 명령이 겹쳐 돌지 않게 한다.
