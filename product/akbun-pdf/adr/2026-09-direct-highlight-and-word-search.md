# 형광펜 즉시 적용과 단어 단위 검색 강조

## 상태

채택

## 맥락

형광펜, 글자 선택, 찾기를 함께 쓰다 보니 읽는 흐름이 세 군데에서 끊겼다.

- 텍스트를 드래그하면 선택 블록이 자주 끊겼다. `.text-layer`의 span 사이에는 빈틈이 있고 body의 `user-select: none`이 span까지 내려오고 있었다.
- 형광펜을 켜고 텍스트를 고르면 색과 내용을 묻는 dialog가 먼저 떴다. 형광펜은 원래 긋는 도구인데 매번 확인을 요구했다.
- 찾기 결과가 텍스트 조각 전체를 강조했다. 한 조각이 문장 하나인 PDF에서는 문장이 통째로 칠해져 어떤 단어가 걸렸는지 보이지 않았다.

## 결정

읽는 화면의 세 가지를 이렇게 정한다.

- text layer의 span에 `user-select: text`를 주고, 드래그하는 동안만 layer 전체를 덮는 빈 요소를 깔아 선택이 끊기지 않게 한다. PDF.js viewer가 `endOfContent`로 쓰는 방법과 같다.
- 형광펜 도구는 선택이 끝나는 즉시 주석을 만든다. 색은 도구를 켤 때 열리는 색 띠에서 미리 고르고 다음 실행까지 기억한다. 내용을 받는 dialog는 메모 도구에만 남긴다.
- 검색 강조는 조각의 사각형을 그대로 쓰지 않고, 일치한 글자 구간만 글자 수에 비례해 잘라 낸다. 결과는 오른쪽 패널에 페이지 번호와 함께 나열한다.

## 이유

- 선택이 끊기는 것은 형광펜과 복사 둘 다를 막는 가장 앞단의 결함이라 CSS와 layer 구조에서 먼저 고쳤다.
- 형광펜은 결과를 눈으로 확인하며 여러 번 긋는 도구다. 확인 창은 한 번의 실수를 막는 대신 열 번의 정상 사용을 느리게 만든다.
- 글자 폭은 text layer에서 알 수 없다. 조각 안에서 글자 수에 비례한다고 보면 비례 글꼴에서도 어긋남이 한 글자를 넘지 않아, 조각 전체를 칠하는 것보다 언제나 낫다.
- 떠 있던 찾기 막대는 본문을 가렸고 결과를 하나씩만 보여 줬다. 목차·AI와 같은 오른쪽 패널로 옮기면 결과 목록을 놓을 자리가 생기고 탭 하나만 늘어난다.

## 결과

- 여러 줄 선택은 줄마다 주석 하나로 나뉜다. PDF 표준 Highlight 하나가 사각형 하나를 가지므로, 줄을 합치면 줄 사이 여백까지 칠해진다.
- 주석만 바뀐 갱신은 페이지를 다시 그리지 않는다. 다시 그리면 읽던 자리에서 스크롤이 튄다.
- 오른쪽 패널 탭이 두 개에서 세 개로 늘었다.
