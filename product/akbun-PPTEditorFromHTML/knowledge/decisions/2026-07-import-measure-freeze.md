## 결정

임포트는 학습지 HTML을 DOMParser로 파싱하고(스크립트가 절대 실행되지 않는다), 각 페이지를 오프스크린 Shadow DOM 캔버스에 1280x720으로 렌더링한 뒤, 페이지의 직계 자식마다 getBoundingClientRect로 위치·크기를 재서 슬라이드 대비 %로 모델에 얼린다. 측정 CSS는 학습지 JS가 없는 상태에서 런타임 초기 화면을 재현한다: 전 페이지 펼침, 표지의 세로 중앙 flex 정렬, stepper 1단계 표시.

## 이유

- 브라우저는 렌더링하면서 모든 요소의 최종 위치를 이미 계산한다. CSS 파싱·박스 모델을 흉내 내는 자체 레이아웃 계산기는 만들 이유가 없고 정확할 수도 없다.
- 좌표를 px가 아니라 %로 두는 것은 논리 해상도가 바뀔 가능성에 대한 보험이고, 편집 시 드래그 수식도 단순해진다.
- 측정이 런타임 초기 상태와 다르면 export에서 어긋난다. 실제로 표지를 block으로 재서 세로 중앙 정렬이 풀린 채 얼어붙는 버그, stepper가 접힌 채 측정돼 export에서 펼쳐지며 아래 객체와 겹칠 뻔한 문제를 측정 CSS로 잡았다.
- 페이지의 직계 자식만 객체로 만든다. 다이어그램 상자 하나하나가 아니라 다이어그램 전체가 한 객체다. PPT의 그룹과 같은 단위이고, 내부는 텍스트 편집으로 고친다.
