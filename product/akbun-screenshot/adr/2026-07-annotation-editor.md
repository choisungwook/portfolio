# 편집기는 shape 목록을 다시 그리는 canvas 한 장

Edit 버튼이 여는 주석 편집기의 구조를 정한 기록이다.

## 결정

편집기는 canvas 한 장이고, 화면은 원본 이미지 위에 shape 배열을 순서대로 다시 그려서 만든다. shape는 좌표와 색과 크기만 가진 평범한 객체다. 픽셀을 직접 고치지 않는다.

되돌리기는 배열의 마지막 shape를 보관 배열로 옮기고 다시 그리는 것이다. 되돌리기의 되돌리기는 반대 방향으로 같은 일을 한다. 화면 스냅샷을 쌓지 않는다.

동그라미 숫자의 다음 번호는 배열에 남은 숫자 shape의 개수로 계산한다. 별도 counter를 두지 않는다.

편집기 창은 원본 이미지를 file 경로가 아니라 data URL로 받는다.

Save와 Close 버튼은 toolbar 오른쪽 끝에 두고, toolbar 자체를 canvas 바깥에 둔다. toolbar가 좁아져 줄바꿈이 일어나도 이 두 버튼은 접히지 않는다.

편집기가 여는 이미지는 preview의 임시 png을 복사한 별도 파일이다.

## 이유

shape 목록을 다시 그리는 방식은 되돌리기를 공짜로 만든다. 픽셀을 직접 고치면 되돌리기마다 canvas 전체를 스냅샷으로 떠야 하고, 4K 스크린샷에서는 한 번 그릴 때마다 수십 MB가 쌓인다.

숫자를 counter로 세면 되돌리기가 번호를 되돌리지 못한다. 3번을 지우고 다시 그리면 4번이 된다. 개수로 계산하면 배열이 곧 번호이므로 이 어긋남이 생기지 않는다.

data URL로 받는 이유는 canvas 오염 때문이다. file:// 페이지에서 file:// 이미지를 canvas에 그리면 Chromium이 canvas를 오염된 것으로 표시하고, 저장에 쓰는 toDataURL이 SecurityError로 막힌다. 같은 바이트를 data URL로 넘기면 canvas가 same-origin으로 남는다.

버튼을 toolbar 오른쪽에 고정하는 이유는 편집기 안에서 저장과 닫기가 스크린샷 내용과 섞이면 안 되기 때문이다. toolbar는 배경색과 아래쪽 경계선으로 구분되고, canvas는 파란 테두리로 자기 영역을 표시한다.

임시 png을 복사하는 이유는 preview를 닫는 순간 preview의 임시 파일이 지워지기 때문이다. Edit은 preview를 닫으므로, 같은 경로를 쓰면 편집기가 이미 지워진 파일을 읽는다.

시스템 폰트 목록은 queryLocalFonts로 읽고, 실패하면 macOS 기본 폰트 네 개로 대체한다. 기본값은 Apple SD Gothic Neo다. macOS에 이미 설치되어 있고 한글과 영어를 모두 그리므로 앱이 폰트를 동봉할 필요가 없다.
