# akbun-taskq 0.35.0

## Added

- 설정 > 연결 맨 위에서 회사 보안 장비의 TLS 검사(SSL 가로채기)용 루트 인증서(PEM)를 가져온다. Claude, OpenAI, Kiro, aws CLI와 taskq 자신이 그 인증서를 믿는다.
- Kiro에 AWS IAM Identity Center 연결을 여러 개 추가하고 그중 하나를 골라 쓴다. 사용 중인 연결은 체크, 강조 테두리, "사용 중" 배지로 보인다. 연결을 바꾸면 그 연결로 AWS SSO 로그인을 다시 한다.
- 상태보드 카드에 실행, 취소, 삭제 버튼이 생겼다. 실행은 채워진 버튼이고, 담당 bot이 없으면 "bot을 정해야 실행"이라고 버튼에 적힌다. 취소와 삭제는 먼저 묻는다.
- 작업 삭제(`DELETE /tasks/:id`). 실행 중이거나 승인을 기다리는 작업은 먼저 취소해야 한다.
- 실패한 작업의 상세에 "실패한 이유"가 보인다. 보고된 내용에서 원인과 해 볼 일을 골라 보인다.
- 작업 상세에 단계(초안함, 진행의 몇 번째 단계, 결과)와 마지막 실행(결과, 시각, 요약)이 따로 보인다.

## Changed

- 작업 상세의 Owner를 "담당 bot"으로 바꾸고, 실패하거나 취소된 작업에도 bot을 고를 수 있게 했다. 다시 실행하려면 bot이 있어야 하기 때문이다.
- 재시도는 언제나 새 세션으로 시작하고, 대신 직전 실행의 결과·요약·마지막 도구 호출을 기억으로 넘긴다. "Resume previous session" 옵션과 실행 기록의 `claude --resume` 복사, 작업 열기 버튼은 없앴다.
- 작업 상세의 제목을 가장 크게, 메타데이터 다음 본문 앞에 여백을 더 두었다.

## Fixed

- 직접 실행한 작업이 매번 "worker returned no valid structured result"로 실패하던 문제. 작업이 결과를 보고하는 `StructuredOutput` 도구를 taskq의 작업 게이트가 "이 작업 유형에 허용되지 않은 도구"로 막고 있었다.
- 데스크톱 앱(WebKit)에서 상태보드 카드를 끌어도 옮겨지지 않던 문제. 카드 버튼에서도 끌기가 시작되게 했다. 데스크톱 앱 껍데기가 끌어 놓기를 가로채지 않게 한 수정은 새 dmg부터 적용된다.

## SDK

작업 실행의 PreToolUse 게이트가 `StructuredOutput`(Options.outputFormat의 결과 도구)을 항상 허용한다.
