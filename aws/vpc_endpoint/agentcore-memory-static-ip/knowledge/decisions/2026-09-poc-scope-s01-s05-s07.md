## 결정

- 유지: S01(hosts 변경·STS), S05(자체 도메인 Route 53 alias만으로 호출하는 실패 확인), S07(CONNECT 프록시, 옵션).
- 삭제: S02·S03·S04·S06·S08 코드·문서·terraform labs, internal-nlb·ra-memory·endpoints 모듈, Roles Anywhere helper·PKI·클라이언트.
- 같은 날 저녁 S02 번호를 재사용해 "앱 네트워크 Squid forward proxy" 시나리오를 새로 만들었다. 옛 S02(VPN·internal NLB)와 무관하다. [근거](2026-09-no-connect-proxy-in-aws.md)
- S05는 별도 NLB를 만들지 않고 S01 Terraform이 STS NLB로 향하는 A alias 레코드 하나를 추가.
- 2026-09-08 S06(자체 도메인 TLS 재암호화 직결)을 S01 root의 opt-in으로 추가. [근거](2026-09-own-domain-tls-nlb-s06.md)
- 인터넷 + public NLB + Roles Anywhere는 아직 없는 시나리오. README 심화학습 항목으로 남기고 나중에 S01에 rolesanywhere endpoint·NLB를 추가하는 형태로 계획.

## 이유

- 실제 요구는 인터넷 outbound IP 허용 목록 환경에서 STS·Memory를 고정 EIP로 호출하는 것. VPN 전제 시나리오는 그 환경과 무관.
- 1시간 PoC 제약. 8개를 유지하면 문서·검증 비용이 목적을 가림.
- 실제 환경의 DNS 변경 가능 여부가 미정이라 hosts 변경(S01)과 자체 도메인 Route 53(S05·S07) 두 갈래를 모두 확인할 필요.
- public hosted zone으로는 amazonaws.com 응답을 바꿀 수 없으므로 Route 53 테스트의 성공 형태는 S07뿐이고, S05는 그 이유를 실제 TLS 오류로 보여 주는 용도.
- Roles Anywhere는 aws/iam/roles-anywhere에서 별도로 학습 중. 여기 다시 넣으면 두 workspace가 같은 인증 코드를 중복 관리.
