# 글쓰기 교정 AI를 위한 context

이 파일은 이 workspace의 문서만 고치는 글쓰기 교정 AI가 읽는 context입니다. 교정 AI는 실습을 다시 실행할 수 없으므로, 무엇을 고쳐도 되고 무엇을 고치면 안 되는지를 여기서 정합니다.

## 이 핸즈온이 말하려는 것

AWS Nitro Sandboxes(2026-11 출시)는 인스턴스 한 대를 여러 워크로드가 나눠 쓰면서, 워크로드마다 Nitro Hypervisor가 경계를 긋는 경량 VM을 주는 기능입니다. 문서는 세 질문에 답합니다.

1. 그 VM은 어떻게 만들어지고, 부모 인스턴스는 그 메모리를 볼 수 있는가 (시나리오 3, EC2 + Firecracker)
2. EKS에서 `runtimeClassName` 한 줄로 바뀌는 것은 무엇인가 (시나리오 5)
3. AI agent가 만든 코드를 가두면 무엇이 막히고, 무엇이 안 막히고, 관측에서 무엇이 빠지는가 (시나리오 6)

문서의 중심은 "무엇이고 왜 필요한가"이고, 실습 절은 그것을 확인하는 증거입니다. 교정할 때 이 무게 중심을 실습 절차 쪽으로 옮기지 않습니다.

## 고쳐도 되는 파일

| 파일 | 고쳐도 되는 것 |
|---|---|
| `README.md`, `docs/*.md` | 문장, 문단 구성, 소제목 문구, 표 안의 설명 문장 |
| `manifests/README.md` | 설명 열의 문장 |

다음 파일은 고치지 않습니다. 코드이거나 실습 결과와 묶여 있어서, 바꾸면 문서와 실제 동작이 어긋납니다.

- `terraform/`, `guest/`, `agent/`, `manifests/**/*.yaml`
- `knowledge/` (형식 규칙이 따로 있음)
- `AGENTS.md`, 이 파일

## 바꾸면 안 되는 내용

교정 AI가 가장 조심할 것은 실측값입니다. 아래는 2026-11-11에 실제로 실행해 얻은 값이라서, 문장을 다듬더라도 숫자와 문자열은 그대로 둡니다.

- `text` 코드블록 안의 출력 전체. 오탈자처럼 보여도 실제 출력입니다(`HTTP Error 404: Not Found`, `000fail` 등).
- 명령, 경로, 설정 키, 리소스 이름: `nitro_enclaves.mempool=2G@0`, `isolated-sandbox`, `sandbox.amazonaws.com/network-isolated`, `executor-sandbox-netoff`, `gemma2:2b`.
- 핵심 수치와 계산.

| 수치 | 위치 | 의미 |
|---|---|---|
| 546MiB, 514MiB | 시나리오 3의 8, 11단계 | confidential, direct 모드의 memory pool 감소량. 공식과 정확히 일치 |
| 표식 0건, 1,988건 | 시나리오 3의 9, 11단계 | 부모가 guest 메모리에서 찾은 표식 수 |
| 6.18.56, 6.18.54 | 시나리오 5, 6 | 노드 커널, sandbox 커널 |
| 193개, 124개 | 시나리오 5의 5단계 | `hostPID`로 보이는 프로세스 수 |
| 256Mi, 약 715Mi | 시나리오 5의 1, 3단계 | RuntimeClass overhead, Sandbox 노드 allocatable 차이 |
| 0.93초, 0.96초 | 시나리오 6의 3단계 | 같은 노드 타입에서 runc, sandbox CPU 과제 |

- `확인 필요`, `추정합니다`로 표시한 문장은 단정형으로 바꾸지 않습니다. 실측하지 않은 부분입니다.
- 시나리오 6의 판정 표는 결론을 담고 있습니다. 특히 "sandbox가 SA 토큰과 외부 인터넷은 막지 못했다", "Container Insights에서 sandbox pod 메트릭이 빠졌다"는 의도한 결론이므로 완화하지 않습니다.

## 용어 고정

한 대상은 한 이름으로 씁니다. 교정하면서 동의어로 바꾸지 않습니다.

| 쓰는 말 | 쓰지 않는 말 |
|---|---|
| Nitro Sandbox, Sandbox | 샌드박스 VM, 마이크로VM(Firecracker 설명 문맥 제외) |
| 부모 인스턴스 | 호스트 인스턴스, 모 인스턴스 |
| confidential 모드, direct 모드 | 기밀 모드, 직접 모드 |
| isolated pod, confidential pod | 격리 파드, 기밀 파드 |
| pod, 노드 | 파드, node |
| memory pool | 메모리 풀, CMA 풀(로그 인용 제외) |
| executor | 실행기 |
| 판정, `allowed`, `blocked` | 성공, 차단(판정 값 자체를 가리킬 때) |

## 문체와 형식

- 저장소 문체 규칙은 루트 `AGENTS.md`의 문서 작성 규칙, `.claude/rules/philosophy.md`, `.claude/rules/markdown.md`를 따릅니다.
- 본문은 `합니다`체입니다. 기존 문서와 섞지 않습니다.
- H1은 파일 맨 위 하나뿐이고, 나머지는 H2부터 씁니다. 코드블록 바로 위에는 그 코드가 무엇인지 설명하는 문장이 있어야 합니다.
- 시나리오 문서의 절 순서(목표 표 → 무엇인가 → 용어 → 왜 필요한가 → 대안 비교 → 컴포넌트 역할 → 흐름 → 실습 → 부록 → 참고 문서)를 바꾸지 않습니다.
- 실습 절의 단계 제목은 `### N. <목적과 동작>` 형식입니다. 단계 번호를 바꾸면 그 번호를 가리키는 다른 문서의 문장(예: "시나리오 3의 6, 7, 10단계")도 같이 고칩니다.
- 개인 IP, 계정 ID, 절대 경로를 새로 넣지 않습니다. 출력에 있는 노드 이름(`i-...`)과 pod IP는 실행마다 달라지는 값이라고 이미 적혀 있으므로 그대로 둡니다.
- 문서 사이 상대 링크(`[4-setup-eks.md](4-setup-eks.md)`)는 파일명을 바꾸지 않는 한 건드리지 않습니다.

## 교정 후 확인할 것

1. `text` 코드블록과 위 수치 표의 값이 교정 전과 같은가.
2. `확인 필요` 표시가 그대로 남아 있는가.
3. mermaid 블록을 고쳤다면 엣지 라벨에 `@`, `:`, `/`가 있을 때 따옴표로 감쌌는가.
4. 용어 고정 표의 "쓰지 않는 말"이 새로 들어가지 않았는가.
