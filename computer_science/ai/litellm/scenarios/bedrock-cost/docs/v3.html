Architecture · LiteLLM × Bedrock

같은 호출을 두 곳이 따로 적는다

client 요청 하나가 LiteLLM의 spend log와 Bedrock의 계량에 각각 기록됩니다. 두 장부는 세는 대상이 달라서 token 수가 어긋납니다. 캐시가 두 군데에 있고, 그중 하나는 Bedrock에 호출을 만들지 않습니다.

INPUT

LiteLLM input이 131배인 이유

  • 42,008 캐시 읽기 — Bedrock은 별도 usage type으로 셉니다
  • 10,502 캐시 쓰기 — 역시 별도입니다
  • 243 응답 캐시 hit의 usage 재기록 — Bedrock에는 호출이 없습니다
  • 403 청구 대상 입력 — 이것만 Bedrock의 input 406에 대응합니다

OUTPUT

output은 방향이 반대입니다

  • 응답 캐시 hit: LiteLLM 2,000 대 Bedrock 200. 저장된 응답을 usage째로 돌려줍니다
  • 끊긴 스트림: LiteLLM 205 대 Bedrock 2,400. client가 2초에 끊어도 Bedrock은 max_tokens까지 생성했습니다

COST

금액은 대부분 맞습니다

  • 시나리오 1~3은 소수 여섯째 자리까지 같습니다. token만 다릅니다
  • 끊긴 스트림만 $0.0034 대 $0.0363입니다
  • Cost Explorer 금액 대조는 데이터가 하루 뒤에 나와 아직 하지 않았습니다
