# 에이전트 코딩은 검증 루프로 운영해요

처음 적용할 방향은 자율성을 키우는 것이 아니라 판정 경계를 선명하게 만드는 일이에요. Codex에게 더 많은 파일과 더 긴 시간을 주기 전에, 무엇을 바꿀 수 있고 누가 완료를 선언하는지부터 고정해요.

## 작업 하나를 작은 상태 머신으로 봐요

권장 흐름은 다음과 같아요.

```text
Issue 또는 task.md
  → Codex가 코드 diff 생성
  → 빠른 결정론적 게이트
  → 실패 이유를 다음 Codex 실행에 전달
  → 독립 holdout과 사람 리뷰
  → merge 또는 중단
```

에이전트가 고치는 대상은 코드예요. 테스트, 정책, 성공 기준까지 동시에 고치게 두면 점수판을 바꾸는 일이 구현보다 쉬워져요.

## 지침은 수명에 따라 나눠요

| 수명 | 저장 위치 | 넣을 내용 |
| --- | --- | --- |
| 한 작업 | Issue, `task.md`, 실행 프롬프트 | 요구사항, 변경 범위, 현재 실패 증거 |
| 저장소 전체 | `AGENTS.md` | 빌드·테스트 명령, 금지 경계, 반복되는 규칙 |
| 실행 결과 | 코드와 diff | 검증할 후보 |
| 회귀 지식 | 테스트 사례 | 다시 발생하면 안 되는 동작 |

한 번 실패한 세부사항을 바로 `AGENTS.md`에 넣지 않는 편이 좋아요. 여러 작업에서 반복되거나 저장소 전체의 판단을 바꾸는 교훈만 지속 지침으로 올려요. 나머지는 회귀 테스트가 더 정확하게 기억해요.

## 게이트는 싼 것부터 쌓아요

| 순서 | 게이트 | 코치에게 공개 |
| --- | --- | --- |
| 1 | formatter, compile, 단위 테스트 | 전체 실패 이유 |
| 2 | 통합 테스트, 정책 검사, 보안 스캔 | 수정 가능한 범위만 공개 |
| 3 | 외부 holdout, 성능 기준 | 통과 여부만 공개 |
| 4 | 사람의 diff 리뷰 | merge 판단에 사용 |

열린 설명이나 UX처럼 코드만으로 판정하기 어려운 항목은 별도 모델 심판을 붙일 수 있어요. 이때도 기능 테스트를 대체하지 않고 보완해요. 동일한 출력 여러 개로 심판의 일관성을 먼저 확인해야 해요.

## 반복 예산은 2~3회부터 시작해요

첫 운영값으로 최대 3회면 충분해요. 통과, 점수 정체, 보호 파일 변경, 실행 실패 중 하나가 발생하면 멈춰요. 횟수를 늘려야만 풀리는 작업은 요구사항 분해나 도구 부족을 먼저 의심해요.

중단된 작업은 실패가 아니라 분류 결과예요. 사람이 새 사례를 승인해 train에 넣거나, 작업을 더 작은 단위로 나누거나, 필요한 도구를 추가할 근거가 생긴 거예요.

## OpenAI 구성은 두 갈래로 나눠요

저장소를 직접 고치는 자동화에는 `codex exec`가 맞아요. 스크립트와 CI에서 실행할 수 있고, `workspace-write` sandbox로 쓰기 범위를 제한할 수 있어요. 기계가 실행 이력을 소비해야 하면 `--json` JSONL 출력도 사용할 수 있어요.

사용자 요청을 받아 도구를 호출하는 제품 에이전트를 만드는 경우에는 Responses API나 Agents SDK가 맞아요. Agents SDK는 도구, handoff, streaming, trace가 필요한 애플리케이션용이에요. 코딩 에이전트의 PR 루프와 제품 런타임을 한 프로세스로 합치지 않는 편이 운영 경계가 선명해요.

OpenAI Evals 플랫폼과 dataset 기반 prompt optimizer는 2026년 종료 일정이 공지되어 있어 새 CI의 필수 의존성으로 두지 않아요. 관련 grader 문서에서 배울 원리는 데이터 세트, 독립 심판, reward hacking 방지, 수동 검토예요. 실행은 저장소 테스트와 현재 CI가 맡아요.

## 프로덕션 실패는 다음 시험으로 바꿔요

장애 로그나 PR 리뷰 지적을 프롬프트 문장으로만 남기면 다시 잊어요. 재현 가능한 입력과 기대 결과로 바꾸고 사람이 확인한 뒤 train에 넣어요. 기존 holdout 사례를 그대로 train으로 옮겼다면 새 holdout도 보충해요.

이렇게 하면 에이전트는 스스로 옳다고 말해서 진화하지 않아요. 반복할수록 통과해야 할 외부 증거가 늘어나기 때문에 진화해요.
