# 시나리오 2.2. SSE 비교 코드 해설

## 같은 모델에 보내는 두 요청

`main()`은 Bearer 인증을 설정한 HTTPX 클라이언트 하나로 비스트리밍 요청과 SSE 요청을 순서대로 보냅니다. 두 요청은 같은 모델 별칭, 프롬프트, 출력 상한, temperature를 사용하고 `stream` 값을 바꿉니다. 두 응답을 Logs에서 찾을 수 있도록 각각 다른 태그도 보냅니다. [실행 순서](../scripts/compare_http_sse.py#L165-L170) · [공통 요청 본문](../scripts/compare_http_sse.py#L43-L51)

클라이언트는 `POST /v1/chat/completions`를 LiteLLM에 보냅니다. LiteLLM은 `local-qwen`을 `ollama_chat/qwen2.5:1.5b`로 해석하고 Docker의 `host.docker.internal:11434`를 통해 macOS에서 실행 중인 Ollama를 호출합니다. [모델 매핑](../config/litellm-config.yaml#L1-L5)

## 응답 본문을 읽는 두 방식

| 동작 | 코드에서 확인할 지점 |
| --- | --- |
| 비스트리밍 요청 | `client.stream()`은 HTTPX가 응답 본문을 읽는 시점을 직접 제어합니다. 서버의 응답 형식은 별도로 JSON의 `stream: false`가 결정합니다. 헤더가 준비되면 시간을 재고, `resp.read()`로 본문 전체를 받아 `message.content`를 한 번에 출력합니다. [비스트리밍 요청과 수신](../scripts/compare_http_sse.py#L54-L84) |
| SSE 요청 | 같은 URL에 `stream: true`를 보내고 `resp.iter_lines()`로 본문을 한 줄씩 읽습니다. `write()` 뒤 `flush()`를 호출해 텍스트 조각을 그때마다 터미널에 표시합니다. [SSE 요청과 수신](../scripts/compare_http_sse.py#L101-L134) |
| 첫 텍스트 판별 | `extract_delta_text()`는 `data:` 줄에서 `[DONE]`과 텍스트 없는 델타를 건너뜁니다. 이 엔드포인트의 한 줄 JSON 페이로드에 맞춘 파서이며, SSE 표준의 여러 `data:` 줄을 합치는 처리는 범용 파서의 역할입니다. [텍스트 추출](../scripts/compare_http_sse.py#L87-L98) |
| 시간 계산 | 각 텍스트 도착 시각을 `perf_counter()`로 기록합니다. 첫 도착 시각을 TTFT로, `(마지막 - 처음) / (조각 수 - 1)`을 평균 청크 간격으로 씁니다. E2E는 전체 본문을 끝까지 읽은 시점의 값입니다. [측정 지점](../scripts/compare_http_sse.py#L116-L145) |

## 클라이언트 측정과 LiteLLM 로그 연결

스크립트는 요청에 `x-litellm-tags`를 실어 비스트리밍에는 `sse-lab-non-stream`, SSE에는 `sse-lab-stream`을 보냅니다. 태그는 Logs에 표시할 요청 측 라벨입니다. 실제 응답 형식은 실습에서 응답의 `Content-Type`과 본문을 보고 확인합니다. [비스트리밍 태그와 헤더](../scripts/compare_http_sse.py#L59-L70) · [SSE 태그와 헤더](../scripts/compare_http_sse.py#L109-L118)

LiteLLM은 PostgreSQL에 요청 로그를 기록하고, 스크립트는 응답 헤더에서 받은 `x-litellm-call-id`를 출력합니다. 같은 태그로 여러 건을 보냈다면 Call ID로 한 요청을 찾습니다. 클라이언트의 TTFT는 로컬 수신 시각을 기준으로 해석합니다. [DB 연결 설정](../compose.yaml#L23-L28) · [Call ID 출력](../scripts/compare_http_sse.py#L154-L162)
