# 시나리오 1.2. 기본 HTTP 부하테스트로 추론 API 기준선 측정

## 이 시나리오의 목표

| 항목 | 내용 |
| --- | --- |
| 기능 | 모델의 비스트리밍 추론 응답을 HTTP로 측정 |
| 도구 | curl, 기본 k6의 `k6/http` |
| 입력 | `qwen2.5:1.5b`, 수동 요청 1건, 가상 사용자 2명의 부하 요청 총 6건 |
| 작업 | 1. curl로 요청·응답 확인 → 2. 같은 API에 k6로 부하 실행 → 3. 지연·실패율·요청 처리량 확인 |
| 달성할 것 | 완성 답변을 받는 API의 HTTP 성능을 설명 |

## 웹 API와 같은 방식으로 호출

모델 추론은 클라이언트 관점에서 HTTP API 한 번의 호출입니다. 프롬프트를 JSON으로 보내고, 모델이 생성한 텍스트를 응답 JSON에서 확인합니다. k6는 기본 HTTP 모듈로 요청에 부하를 주고, Ollama에서 실행하는 모델은 중간 게이트웨이를 통해 응답합니다. [모델 매핑](../config/litellm-config.yaml#L1-L5)

- 가상 사용자(VU) 두 명이 앞선 응답을 받은 뒤 다음 요청을 보냅니다. 두 사용자가 합쳐서 총 6건을 실행합니다. [가상 사용자와 반복 설정](../k6/00-http-baseline.js#L8-L11)
- `http.post()`는 기존 웹 API를 테스트할 때처럼 URL, JSON 본문, 헤더를 받습니다. 모델 별칭과 프롬프트를 담고 `stream: false`로 완성된 답변을 요청합니다. [요청 본문과 POST 호출](../k6/00-http-baseline.js#L13-L31)
- HTTP 200과 `choices[0].message.content`의 텍스트를 함께 검사합니다. 생성된 텍스트가 비어 있는 경우는 HTTP 상태 코드만으로 구분하기 어렵습니다. [응답 검사](../k6/00-http-baseline.js#L33-L39)

## 실습 · 3분

[환경 준비](setup.md)를 마친 뒤 핸즈온 디렉터리에서 실행합니다.

### 1. curl로 요청 한 건 확인

k6가 호출할 `POST /v1/chat/completions`에 같은 모델과 프롬프트, 생성 옵션을 보내 봅니다. `[req-1-0]`은 첫 번째 가상 사용자의 첫 요청에 붙는 접두사입니다. `-i`로 응답 헤더와 본문을 함께 봅니다. [k6 요청 코드](../k6/00-http-baseline.js#L13-L31)

```bash
curl -sS -i --max-time 60 \
  -X POST http://localhost:4000/v1/chat/completions \
  -H 'Authorization: Bearer sk-local-litellm-test' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "local-qwen",
    "messages": [
      {
        "role": "user",
        "content": "[req-1-0] 쿠버네티스 Pod와 Deployment의 차이를 4문장으로 설명해 주세요."
      }
    ],
    "max_tokens": 100,
    "temperature": 0.2,
    "stream": false
  }'
```

응답에서 `200 OK`, `content-type: application/json`, `choices[0].message.content`의 생성 텍스트를 찾습니다. k6도 각 요청에서 이 값을 검사합니다. [k6 응답 검사](../k6/00-http-baseline.js#L33-L39)

### 2. 같은 API에 k6로 부하 실행

수동 호출에서 확인한 API에 가상 사용자 두 명으로 총 6건을 보냅니다. 앞서 보낸 curl 요청은 k6 통계 집계에 포함되지 않습니다.

```bash
k6 run k6/00-http-baseline.js
```

M3 Pro에서 수동 호출 직후 실행한 예입니다. 각 요청에서 상태 코드와 생성된 텍스트를 검사해 총 12개 검사가 통과했습니다.

| 기록할 지표 | 실측값 | 읽는 법 |
| --- | ---: | --- |
| `http_req_duration` P95 | 3.48초 | 요청 전송, 응답 대기, 본문 수신 시간의 합을 집계한 95번째 백분위수 |
| `http_req_failed` | 0/6건 | k6의 HTTP 실패 판정에 해당하는 요청 수 |
| `http_reqs` | 6건, 약 0.59건/초 | 해당 실행에서 보낸 요청 수와 초당 평균 요청 수 |

이 숫자는 가상 사용자 두 명이 요청하는 동안 클라이언트가 관측한 결과입니다. 여섯 요청은 지표의 의미를 확인하는 데 쓰고, 부하 한계는 동시성과 요청 수를 늘려 따로 확인합니다. 채팅 화면에서 더 일찍 텍스트를 보여 주려면 언제 표시할 수 있는지가 다음 질문입니다. [SSE 이론](2.1-sse-theory.md)
