# Haru 레이아웃 선택 지침과 SSE 예제

## 에이전트에게 전달할 범용 지침

아래 지침은 주제가 주어졌을 때 읽는 사람이 확인할 관계를 먼저 정하고, 그 관계를 표현할 Haru 레이아웃을 고르는 데 사용합니다.

```text
1. 그림을 본 사람이 무엇을 이해해야 하는지 한 문장으로 적는다.
   입력에서 개체, 역할, 화살표 방향, 경계, 시간 순서를 뽑는다.
2. 주제에서 가장 중요한 관계로 레이아웃 후보를 정하고
   Haru의 layouts.jsonl에 실제로 등록된 레이아웃을 확인한다.
   - 단계가 순서대로 이어지면 row, column, columns를 고려한다.
   - 중심과 여러 개체의 연결이면 hub, 소속과 계층이면 layers를 고려한다.
   - 전후 비교나 입력과 결과의 대응이면 split 또는 stack을 고려한다.
   - 상태가 처음으로 돌아오면 loop를 고려한다.
   - 같은 참여자들이 시간 순서대로 메시지를 주고받으면
     참여자별 세로선과 메시지별 수평 화살표가 있는 시퀀스를 고려한다.
3. 등록된 레이아웃이 방향·순서·관계를 보존하면 스펙을 만들고
   Haru 빌더를 사용한다. 직접 대응하는 레이아웃이 없으면 부족한 점을
   적고, 필요한 형태를 작업 폴더의 로컬 스펙으로 정의한다.
4. 색은 주제를 읽는 데 필요한 의미에 배정한다. 표현할 역할에 맞는
   등록 팔레트를 먼저 확인한다. 요청·응답·이벤트를 구분하는
   시퀀스라면 하늘색·옅은 노랑·분홍을 라벨 뒤에만 쓴다.
   선과 글씨는 잉크색, 참여자 박스 내부와 캔버스는 흰색으로 둔다.
5. 렌더링한 뒤 화살표 방향, 메시지 순서, 색과 역할의 대응,
   경계의 범위를 입력과 대조한다. 선택 이유와 생성 프롬프트를 남긴다.

SSE 예제
- 누가 언제 무엇을 보내는지 보여 줄 때는 시퀀스를 사용한다.
  Client → Server 요청, Server → Client 응답 헤더,
  첫 이벤트까지의 대기, 후속 이벤트를 시간순으로 놓는다.
  응답 헤더와 이벤트만 묶어 한 HTTP 응답임을 표시한다.
- 빈 줄 앞의 data 줄이 어떤 이벤트로 파싱되는지 보여 줄 때는
  Haru의 split을 써서 왼쪽 원본 본문과 오른쪽 이벤트를 줄마다 대응시킨다.
```
