SELinux와 dm-verity 시뮬레이터

SELinux는 실행 중인 프로세스가 무엇을 할 수 있는지 제한하고, dm-verity는 디스크의 OS 이미지가 빌드한 그대로인지 블록마다 검증합니다. 두 기능을 직접 조작해 판정 과정을 따라가 봅니다.

SELinux 접근 판정 dm-verity 해시 트리 둘의 역할 비교
1 · Type Enforcement와 MCS

이 접근은 허용될까?

프로세스(subject)와 대상(object)의 label을 고르면 커널이 거치는 검사 순서와 결과, 거부될 때 audit.log에 남는 AVC 한 줄을 보여 줍니다. 규칙은 RHEL 계열 targeted 정책과 container-selinux 정책을 단순화했습니다.

    2 · Merkle 해시 트리
    
    
    블록 하나가 바뀌면 어디서 탐지될까?
    
    
    데이터 블록 8개로 만든 해시 트리입니다. 블록을 눌러 변조한 뒤 읽기를 실행하면 커널이 그 블록에서 root hash까지 올라가며 비교하는 경로를 표시합니다. 실제 dm-verity는 4KiB 블록과 SHA-256을 쓰고 해시 블록 하나에 해시 128개를 담습니다.

    3 · Bottlerocket에서
    
    
    둘은 서로 다른 공격을 막는다
    
    
    
      
    
        
    SELinuxdm-verity
    
        
          
    보호 대상실행 중인 프로세스의 행동디스크에 있는 OS 이미지 블록
    
          
    판정 시점syscall마다 LSM hook에서블록을 읽을 때마다
    
          
    기준부팅 때 로드한 정책의 allow 규칙서명된 부트 체인이 넘긴 root hash
    
          
    위반 시EACCES, AVC 로그EIO, Bottlerocket은 재부팅
    
          
    못 막는 것정책이 허용한 행동, 커널 취약점쓰기 가능한 파티션, 메모리 변조
    
          
    Bottlerocket 설정enforcing 고정, container_t · control_t · super_t루트 파티션 전체, restart_on_corruption
